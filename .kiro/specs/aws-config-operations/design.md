# Design Document: AWS Config Operations Module

## Overview

This document describes the architecture and design of `Config-Operations.psm1`, a PowerShell module providing four functions for querying AWS Config resource lifecycle data and compliance status. The module integrates with the existing CharlandCustomizations project patterns, using `New-AWSParamSplat` for credential splatting, `Test-CHARAWSCmdlet` for cmdlet validation, and PSCustomObject output for pipeline compatibility.

## Architecture

### Module Structure

```
src/CharlandCustomizations/
├── Private/
│   └── New-AWSParamSplat.ps1          # Credential splat builder
├── Public/
│   ├── Test-CHARAWSCmdlet.ps1         # Cmdlet availability validator
│   └── AWS/
│       └── Config/
│           └── Config-Operations.psm1  # All four Config functions
```

The module follows the established single-file pattern (like `S3Customizations.psm1` and `AWSCustomizations.psm1`) where all related functions live in one `.psm1` file. Helpers are dot-sourced at module load using relative paths:

```powershell
. "$PSScriptRoot/../../../Private/New-AWSParamSplat.ps1"
. "$PSScriptRoot/../../Test-CHARAWSCmdlet.ps1"
```

### Execution Flow

Every exported function follows an identical three-block pattern:

```
begin {
    1. Validate required AWS cmdlets via Test-CHARAWSCmdlet
    2. Build credential splat via New-AWSParamSplat
}
process {
    3. Call AWS APIs with @awsParams splatting
    4. Transform results into ordered PSCustomObjects
    5. Emit objects individually to output stream
}
end { }
```

This pattern ensures cmdlet validation happens once per pipeline invocation, credential parameters are resolved once, and each input object processed in the pipeline produces output without buffering.

### Component 2: Get-CHARConfigResourceCreationDate

Determines when a resource was first recorded by AWS Config and correlates with CloudTrail to identify the creating principal.

**AWS Cmdlets Required:**
- `Get-CFGResourceConfigHistory` — retrieves configuration item history
- `Find-CTEvent` (CloudTrail `LookupEvents`) — searches for the creation API event

**Logic:**
1. Query `Get-CFGResourceConfigHistory` with `EarlierTime` set to the earliest possible date, sorted chronologically
2. Extract the earliest configuration item's `ConfigurationItemCaptureTime` as the creation date
3. Query `Find-CTEvent` with the resource ID and a time window around the creation date
4. Filter CloudTrail events for creation-type API calls (e.g., `RunInstances`, `CreateBucket`)
5. Extract `PrincipalName`, `EventName`, `EventSource` from the matching event

### Component 3: Get-CHARConfigResourceDeleteDate

Determines when a resource was deleted and correlates with CloudTrail to identify the deleting principal.

**AWS Cmdlets Required:**
- `Get-CFGResourceConfigHistory` — retrieves configuration item history
- `Find-CTEvent` (CloudTrail `LookupEvents`) — searches for the deletion API event

**Logic:**
1. Query `Get-CFGResourceConfigHistory` for the resource
2. Filter for configuration items where `ConfigurationItemStatus` equals `ResourceDeleted`
3. Extract the deletion timestamp from the matching item
4. Query `Find-CTEvent` around the deletion timestamp for the resource ID
5. Filter CloudTrail events for deletion-type API calls
6. Extract `PrincipalName`, `EventName`, `EventSource` from the matching event

### Component 4: Get-CHARConfigNonCompliantResource

Retrieves all resources evaluated as non-compliant by a specified Config rule.

**AWS Cmdlets Required:**
- `Get-CFGComplianceDetailsByConfigRule` — retrieves evaluation results for a rule

**Logic:**
1. Query `Get-CFGComplianceDetailsByConfigRule` with `ComplianceType` set to `NON_COMPLIANT`
2. Handle pagination (the AWS cmdlet handles this via `-Select *` or iteration)
3. Transform each evaluation result into an output object
4. Emit each object individually for pipeline streaming

### Component 5: Get-CHARConfigResourceComplianceReport

Retrieves all Config rule evaluations associated with a specific resource.

**AWS Cmdlets Required:**
- `Get-CFGComplianceDetailsByResource` — retrieves compliance evaluations for a resource

**Logic:**
1. Query `Get-CFGComplianceDetailsByResource` with the resource ID and type
2. Handle pagination
3. Transform each evaluation result into an output object with rule name, compliance type, and last evaluated time

## Error Handling

### Error Strategy

| Condition | Behavior | Stream |
|-----------|----------|--------|
| Required AWS cmdlet unavailable | `Test-CHARAWSCmdlet` throws terminating error | Error (terminating) |
| Resource has no Config history | `Write-Warning` with resource ID, return `$null` | Warning |
| Resource has no deletion record | `Write-Warning` with resource ID, return `$null` | Warning |
| Config rule does not exist | `Write-Error` with rule name, terminate | Error (non-terminating via `$PSCmdlet.WriteError`) |
| Config rule has no non-compliant resources | `Write-Verbose` message, return empty collection | Verbose |
| Resource has no compliance evaluations | `Write-Warning` with resource ID, return empty collection | Warning |
| AWS API permission error | `Write-Error` with action name and AWS error message | Error |
| AWS service exception | `Write-Error` with service, operation, and exception detail | Error |

### Try/Catch Pattern

Each AWS API call is wrapped in a try/catch that distinguishes permission errors from general service exceptions:

```powershell
try {
    $history = Get-CFGResourceConfigHistory @awsParams -ResourceId $ResourceId -ResourceType $ResourceType
}
catch [Amazon.ConfigService.Model.ResourceNotDiscoveredException] {
    Write-Warning "Resource '$ResourceId' ($ResourceType) has no configuration history in AWS Config."
    return $null
}
catch {
    $errorMessage = $_.Exception.Message
    if ($errorMessage -match 'AccessDenied|not authorized') {
        Write-Error "Access denied querying Config history for '$ResourceId': $errorMessage"
    }
    else {
        Write-Error "AWS Config API error for '$ResourceId': $errorMessage"
    }
    return
}
```

## Verbose Output Strategy

Each function emits `Write-Verbose` messages at key operational milestones:

1. Start of operation with resource identifier
2. Number of history items retrieved
3. CloudTrail lookup parameters and result count (for creation/deletion functions)
4. Number of compliance results found (for compliance functions)

### Property Reflection

Reviewing all identified properties for redundancy:

1. **Properties 4.6 and 5.6** (output object structure for creation/deletion) — these test the same pattern but for different functions with different property names. Keep both as they validate different output schemas.

2. **Properties 4.7 and 5.7** (CloudTrail unavailable → null fields) — same pattern, different functions. Can be combined into one property that covers both functions.

3. **Properties 4.8 and 5.8** (no history → warning + null) — same pattern for different absence conditions. Can be combined.

4. **Properties 6.4, 7.5** (output structure for compliance functions) — different schemas, keep separate.

5. **Property 8.1** (ordered properties) subsumes part of 4.6/5.6/6.4/7.5 regarding property presence. However, 8.1 specifically tests *ordering* while the function-specific properties test that the *correct* properties exist for each function. Keep 8.1 as a cross-cutting property and consolidate the function-specific ones into it.

6. **Properties 8.2-8.3** (pipeline streaming) — these are the same requirement. Combine into one property.

**Consolidation decisions:**
- Combine 4.7 + 5.7 into one property about CloudTrail unavailability across both lifecycle functions
- Combine 4.8 + 5.8 into one property about missing Config history across both lifecycle functions
- Combine 4.6 + 5.6 + 6.4 + 7.5 + 8.1 into one comprehensive output structure property
- Keep 8.2/8.3 as one pipeline streaming property
- Keep 3.2 (cmdlet validation termination)
- Keep 6.5 (invalid rule → error)
- Keep 6.6 (no non-compliant resources)
- Keep 9.1/9.2 (error context) as one property
- Keep 2.1 (AWS common parameters present)

### Property 1: AWS common parameters present on all exported functions

*For any* exported function in the Config module, the function SHALL declare all 8 AWS common parameters (Region, ProfileName, AccessKey, SecretKey, SessionToken, Credential, ProfileLocation, EndpointUrl) as optional parameters.

**Validates: Requirements 2.1**

### Property 2: Cmdlet validation failure prevents API execution

*For any* exported function in the Config module, if `Test-CHARAWSCmdlet` throws a terminating error, then no AWS service API cmdlet SHALL be invoked.

**Validates: Requirements 3.2**

### Property 3: Output objects have correct schema and property order

*For any* successful invocation of an exported function that produces non-null output:
- `Get-CHARConfigResourceCreationDate` SHALL return an object with exactly properties `ResourceId`, `ResourceType`, `CreationDate`, `PrincipalName`, `EventName`, `EventSource` in that order
- `Get-CHARConfigResourceDeleteDate` SHALL return an object with exactly properties `ResourceId`, `ResourceType`, `DeletionDate`, `PrincipalName`, `EventName`, `EventSource` in that order
- `Get-CHARConfigNonCompliantResource` SHALL return objects with exactly properties `ResourceId`, `ResourceType`, `ComplianceType`, `ConfigRuleName` in that order
- `Get-CHARConfigResourceComplianceReport` SHALL return objects with exactly properties `ResourceId`, `ResourceType`, `ConfigRuleName`, `ComplianceType`, `LastEvaluatedTime` in that order

**Validates: Requirements 4.6, 5.6, 6.4, 7.5, 8.1**

### Property 4: Missing CloudTrail data produces null correlation fields

*For any* invocation of `Get-CHARConfigResourceCreationDate` or `Get-CHARConfigResourceDeleteDate` where AWS Config returns a valid history item but CloudTrail returns no matching events, the output object SHALL have `PrincipalName`, `EventName`, and `EventSource` all set to `$null`, while still providing a valid date field.

**Validates: Requirements 4.7, 5.7**

### Property 5: Absent Config history returns null with warning

*For any* resource identifier where AWS Config has no configuration history (for creation date lookup) or no deletion record (for deletion date lookup), the function SHALL return `$null` and emit a warning message containing the resource identifier.

**Validates: Requirements 4.8, 5.8**

### Property 6: Non-existent Config rule produces terminating error

*For any* Config rule name that does not exist in the AWS account, `Get-CHARConfigNonCompliantResource` SHALL emit an error message containing the rule name and SHALL not return any output objects.

**Validates: Requirements 6.5**

### Property 7: Fully compliant rule returns empty collection with verbose message

*For any* valid Config rule that has zero non-compliant resources, `Get-CHARConfigNonCompliantResource` SHALL return an empty collection and emit a verbose message indicating full compliance.

**Validates: Requirements 6.6**

### Property 8: Pipeline streaming emits objects individually

*For any* function invocation that produces multiple results, each PSCustomObject SHALL be emitted individually to the output stream (not collected into an array before output), enabling downstream pipeline cmdlets to process items as they arrive.

**Validates: Requirements 8.2, 8.3**

### Property 9: Error messages include specific context

*For any* AWS API failure, the error message emitted by the module SHALL include the specific action that failed and the AWS error detail. Permission errors SHALL reference the denied action; service exceptions SHALL reference the service name and operation.

**Validates: Requirements 9.1, 9.2**

```powershell
Describe '<FunctionName>' -Tag 'Unit' {

    }

    Context 'Happy path' {
        It 'Returns correct output object with expected properties' { }
        It 'Returns properties in documented order' { }
    }

    Context 'CloudTrail unavailable' {
        # Only in lifecycle function tests
        It 'Returns null CloudTrail fields when no events found' { }
    }

    Context 'No Config history / No results' {
        It 'Returns $null and emits warning for missing history' { }
    }

    Context 'AWS API errors' {

    }

    }
```
